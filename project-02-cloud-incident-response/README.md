# Project 02 — Cross-Border Cloud Support & Incident Response

## Business Background
During my experience developing the Japanese market for a Taiwan-based B2B SaaS company, enterprise customers frequently raised concerns about technical support availability, response times, and local points of contact.

I left the company during the implementation stage, so this project uses a hypothetical post-launch scenario inspired by real customer concerns rather than incidents I personally handled.

## Business Problem
When an international SaaS company expands into a new market, customer issues may be reported to local business development staff or distributors before reaching overseas engineers.

Without monitoring and clear escalation procedures, technical incidents can create delays, confusion, and loss of customer trust.

## Proposed Solution
Design an AWS-based cloud monitoring and incident response solution using Terraform, EC2, CloudWatch, SNS, and Linux.

## Project Goals
- Detect infrastructure issues through CloudWatch alarms.
- Notify technical contacts through SNS.
- Define responsibilities for local BD, distributors, and HQ engineers.
- Document troubleshooting and customer communication procedures.
- Demonstrate a reproducible, cost-conscious cloud operations design.

## Project Status
Design phase. AWS deployment and incident simulation are pending.
